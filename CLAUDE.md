# CLAUDE.md

Заметки для любой Claude-сессии (в том числе коллеги), которая открывает этот репозиторий.
Обновляйте по ходу работы — устаревший файл хуже, чем его отсутствие.

## Что это за проект

«Без Вступительных» — сервис подготовки к перечневым олимпиадам по физике и математике.
Тэглайн: «База вузов — получи своё БВИ в вуз мечты». Подробности продукта и экранов —
в [README.md](README.md).

## Архитектура

- **Фронтенд** — `/src`, Vite + React 18 + TailwindCSS 3, без роутер-библиотеки (свой
  хэш-роутер в [App.jsx](src/App.jsx)), без UI-кита. Данные — через `fetch` к бэкенду, см.
  [src/lib/api.js](src/lib/api.js).
- **Бэкенд** — `/backend`, FastAPI + SQLAlchemy 2.0 (async, asyncpg) + Alembic, БД —
  облачный PostgreSQL на Neon. Подробности — [backend/README.md](backend/README.md).

Раньше это был чисто фронтенд-прототип на захардкоженных данных (`src/data/*.js`). Теперь
контент (разделы/темы/задачи/олимпиады/вузы/тарифы) и прогресс пользователя — в БД, отдаёт их
бэкенд. В `src/data/` остались только презентационные константы без бэкенд-аналога:
`topics.js` — tailwind-классы уровней сложности, `site.js` — маркетинговый копирайт лендинга
и статусные цвета кабинета. **Не добавляйте туда контент заново** — новые темы/олимпиады/вузы
редактируются через `backend/scripts/seed_data.py` (см. ниже).

## Запуск

Бэкенд и фронтенд запускаются раздельно, порядок важен — фронтенд без бэкенда покажет
ошибки загрузки на каждой странице, кроме статичных частей лендинга.

1. Бэкенд: [backend/README.md](backend/README.md) — venv, `.env` со строкой подключения к
   Neon, `alembic upgrade head`, `python -m scripts.seed`, `uvicorn app.main:app --reload
   --port 8000`.
2. Фронтенд: `npm install && npm run dev` в корне (порт 5173, `VITE_API_URL` по умолчанию
   смотрит на `localhost:8000/api`, см. `.env.example`).

### Запуск без доступа к Neon (локальный Postgres)

Строка подключения к Neon есть только у того, кто создавал проект, — `backend/.env` не в
гите. Чтобы поднять всё локально без неё, нужен любой Postgres, SSL выключается переменной:

```
DATABASE_URL=postgresql+asyncpg://postgres@localhost:5433/bvi
DATABASE_SSL=disable
JWT_SECRET=<любая случайная строка>
CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
```

Дальше как обычно: `alembic upgrade head` → `python -m scripts.seed` → `uvicorn`.

Подводные камни, на которые наткнулись (2026-09-18):
- `DATABASE_SSL` (в `app/config.py`, по умолчанию `require`) добавлен потому, что раньше
  `ssl="require"` был жёстко зашит в `app/database.py` и локальный Postgres без SSL не
  подключался. Для Neon ничего не меняется — просто не задавайте переменную.
- Postgres из pip-пакета `pgserver` (удобен без Docker/админ-прав) **не работает из папки с
  кириллицей в пути** — `initdb` падает с `invalid byte sequence for encoding "UTF8"`.
  Наша папка — `…\Рабочий стол\ии олимпиады`, поэтому бинарники (`pgserver/pginstall`)
  копировали в папку с латинским путём и запускали `initdb --no-locale` / `pg_ctl` оттуда.
  Ещё у этой сборки нет SSL — отсюда и `DATABASE_SSL=disable`.
- Тесты раньше падали при общем прогоне (`pytest` целиком: 2 из 6 с
  `Event loop is closed` / `'NoneType' ... 'send'`), хотя по одному проходили:
  pytest-asyncio даёт каждому тесту новый event loop, а пул соединений engine глобальный.
  Починено автоматической фикстурой в `tests/conftest.py`, которая после каждого теста
  делает `engine.dispose()`. **После обновления кода сначала `alembic upgrade head`
  (сейчас последняя миграция `0003`), потом `python -m scripts.seed`** — иначе сид упадёт на
  отсутствующих таблицах.
- `uvicorn --reload` в этой папке (OneDrive + кириллица в пути) не замечает изменений файлов —
  после правок бэкенда перезапускайте uvicorn руками.

## Ключевые решения и почему

- **Пейвол — серверный, не клиентский.** Раньше был чекбокс «Режим подписчика» на фронте
  (чисто декоративный). Теперь `GET /topics/{id}` сам решает, показывать ли текст
  medium/hard-задач, по `topic.free` и `user.subscription_active`. Чекбокс убран
  ([TopicPage.jsx](src/pages/TopicPage.jsx)).
- **Прогресс не хранится агрегатом, а считается на лету** из таблицы `task_attempts`
  (одна строка на пару пользователь+задача) — см. `backend/app/crud/progress.py`. Так нет
  риска рассинхронизации агрегата с реальными попытками.
- **Нет отдельной тестовой БД.** Локально Postgres/Docker нет (проверяли — на машине их
  просто не было), используется один и тот же облачный Neon и для dev, и для тестов
  (`backend/tests/`, смотрят на `.env`).
- **Content-часть бэкенда без своего redeploy-пайплайна.** `scripts/seed_data.py` —
  вручную перенесённые данные из бывших `topics.js`/`site.js`, идемпотентно
  апсертятся `python -m scripts.seed`. Если меняете контент — правьте там, затем
  перезапускайте сид.
- **Нет UI-кнопки «отметить задачу решённой».** Эндпоинт `POST /progress/attempts`
  есть и протестирован (curl/Swagger), но на `TopicPage` пока не подключена кнопка —
  бэкенд не отдаёт per-task статус «решено/не решено» в `GET /topics/{id}`, только
  агрегат по теме. Если понадобится кнопка — сначала расширить `TaskOut`.
- **Auth упрощён осознанно.** Один JWT на 7 дней, без refresh-токенов и подтверждения
  email — нормально для прототипа, но не для продакшена.
- **Программа по классам — отдельная сущность, а не темы каталога** (добавлено
  2026-09-18). Учебный план по физике для 9/10/11 класса устроен как «класс → тема →
  подтема (занятие)», и у подтем нет конспектов и задач — это другое, чем темы каталога
  («раздел → тема с задачами»). Поэтому это свои таблицы `curriculum_modules` /
  `curriculum_lessons` (миграция `0002`), ручка `GET /api/curriculum?subject=physics` и
  страница `#/program` ([Program.jsx](src/pages/Program.jsx)); каталог и его темы не
  тронуты. Подтема может ссылаться на тему каталога (`topic_id`, nullable, `SET NULL`) —
  тогда на странице есть ссылка «Задачи по теме». Данные — в
  [backend/scripts/curriculum_data.py](backend/scripts/curriculum_data.py), сид пересобирает
  программу целиком (delete + insert), так что правки/удаления уроков отрабатывают
  корректно. Математики в программе пока нет — ручка вернёт `[]`.
- **Задачи из задачников привязаны к подтемам программы** (добавлено 2026-09-18). Таблицы
  `problem_sources` + `lesson_problems` (миграция `0003`), ручка
  `GET /api/curriculum/lessons/{id}/problems`, у подтем в `/api/curriculum` есть
  `problem_count`; на `#/program` у подтемы кнопка «Задачи из сборника · N». Первый задачник —
  **Савченко О. Я., Балдин Е. М. «Сборник задач по физике», 2003**: все 146 задач (§1.1–§2.1),
  данные в [backend/scripts/problems_savchenko_baldin.py](backend/scripts/problems_savchenko_baldin.py),
  рисунки и ответы — картинки в `public/problems/savchenko-baldin/{fig,ans}/<номер>.png`
  (59 рисунков, 127 ответов; у главы 2 ответов в книге нет, у 1.4.12 тоже).
- **Лицензия этого сборника — GNU FDL, и у неё есть обязательства:** на сайте всегда указаны
  авторы, название и лицензия (делает фронтенд под списком задач); производные тексты остаются
  под GNU FDL; **авторы запретили добавлять решения к задачам** («это не решебник») — не
  подключайте к этим задачам подсказки/разборы/кнопку ИИ-решения; задачи открыты без пейвола.
  GFDL требует прикладывать текст лицензии — **пока не сделано** (нужно положить текст
  GNU FDL в репозиторий, например `LICENSES/GFDL-1.3.txt`).
- **Другие задачники (Гольдфарб, «Квант», mathus.ru и т.п.) так переносить нельзя** —
  они под обычным авторским правом, без свободной лицензии. Варианты — ссылки на источник и
  свои задачи «по мотивам»; как наполнять — решение отложено (обсуждалось 2026-09-18).
  Перед переносом любого нового сборника сначала проверьте его лицензию.
- **Как готовились данные сборника** (скрипты разовые, в репозиторий не клали): текстовый
  слой PDF через pypdfium2 (у pypdf кириллица TeX-шрифтов идёт кракозябрами), затем каждая
  задача вычитана вручную по отрендеренным страницам — формулы в текстовом слое теряются
  (индексы, степени, греческие буквы, дроби). Исправлены явные опечатки оригинала, они
  перечислены в шапке и комментариях файла данных. Рисунки — векторные кластеры страницы,
  привязанные к задаче по подписи «Рис. … К задаче №…», часть рамок задана вручную. Ответы
  вырезаны от номера до следующего номера (граница — по пустой полосе между строками), чужие
  рисунки на страницах ответов закрашены. Привязка задачи к подтеме — ручная, в том же файле.
- **Что в плане программы надо перепроверить с автором плана** (подробнее — в шапке и
  комментариях `curriculum_data.py`): в 11 классе у занятий 47–72 в исходнике не было
  названий и номеров — названия сформулированы по описаниям; в 10 классе описания
  занятий 5 и 6 дословно совпадают с 7 и 8 (похоже на ошибку копирования); у 10 кл.
  №53 вместо описания было «K sigma omega».

## На что обратить внимание в этом окружении (Windows)

- На этой машине изначально не было ни Node.js, ни Python-тулинга под бэкенд — оба
  ставили по ходу работы (Node — через `winget install OpenJS.NodeJS.LTS`).
- После установки Node.js уже запущенные процессы (включая сам харнесс Claude Code) не
  видят обновлённый PATH, пока их не перезапустят — приходится вызывать `node`/`npm` по
  полному пути (`C:\Program Files\nodejs\...`) внутри уже открытой сессии.
- В Git Bash на Windows `nohup команда &` не переживает завершение самого bash-вызова —
  для долгоживущих фоновых процессов (`uvicorn`, `vite`) используйте способ, который
  инструмент явно поддерживает как персистентный (в Claude Code — параметр
  `run_in_background` у Bash), а не голый `nohup`.

## Секреты

`backend/.env` содержит боевую строку подключения к Neon — никогда не коммитить (уже в
`.gitignore`). `JWT_SECRET` в текущем `.env` — dev-значение, для настоящего продакшена
нужно сгенерировать новое и не шарить его в чатах/логах.
