# Большие интерактивные конспекты по физике

Исходники конспектов по физике и сборщик. Готовые страницы (~0,8 МБ) в git не лежат —
их собирает `build.py` в `dist/` (папка в `.gitignore`), а на сайт они попадают через базу
так же, как конспекты по математике (см. CLAUDE.md, «Большие интерактивные конспекты»).

| Файл | Что это |
| --- | --- |
| `physics/NN.html` | Текст темы NN короткими тегами: подтемы, формулы, задачи |
| `physics/NN.js` | Живые модели темы (`FIG(...)` — формат движка) |
| `checks/NN_*.py` | Проверка всех чисел темы кодом, независимо от текста |
| `shell.html` | Общая оболочка: стили, шрифты, KaTeX и движок из конспектов по математике |
| `toc_shell.html` | Оболочка оглавления «00» |
| `build.py` | Сборщик |

## Как сделать или поправить тему

1. Проверить числа: `python conspects/checks/01_kinematics.py` — все `assert` должны пройти.
2. Собрать: `backend/.venv/Scripts/python conspects/build.py` (нужен venv бэкенда — сборщик
   берёт названия подтем из программы `backend/scripts/curriculum_*.py`).
3. Посмотреть: открыть `conspects/dist/physics/NN ….html` через любой локальный сервер
   (`python -m http.server` в этой папке) — с `file://` браузер может не открыть.
4. Загрузить в базу:
   `python -m scripts.load_conspects <путь>/conspects/dist/physics --subject physics`
   (из `backend/`, сначала с `--dry-run`). На проде — то же самое на сервере после копирования
   папки `dist/physics`, как описано в CLAUDE.md для математики.

## Короткие теги исходника

Сборщик разворачивает их в разметку движка; шапку, карту темы, заголовки подтем и
шпаргалку он строит сам из программы, поэтому названия всегда совпадают с базой.

```html
<!--meta
lead: аннотация темы
pre: что знать заранее | через | вертикальную черту
books: «Что почитать» — книги и главы по названию, без номеров страниц
-->
<section n="1">                       <!-- номер подтемы по порядку программы -->
  <eq n="1.1">\[x=x_0+v_xt\]</eq>     <!-- нумерованная формула -->
  <thm n="1.1" t="Закон">…</thm>
  <fig id="meet" n="1.1" cap="подпись">описание модели</fig>
  <lim><ul><li>…</li></ul></lim>      <!-- границы применимости -->
  <err><ul><li>…</li></ul></err>      <!-- типичные ошибки -->
  <calc>…</calc>                      <!-- «для 10–11 классов: вывод с производными» -->
  <tricks><t b="Название">суть, <i>Пример:</i> …</t></tricks>
  <wp n="1.Р1" src="Своя"><q>…</q><idea>…</idea><r>…</r><chk>…</chk></wp>
  <ex n="1.С1" s="2" src="Своя"><q>…</q><h>…</h><a>…</a><r>…</r></ex>
  <cheat><li>пункт шпаргалки</li></cheat>
</section>
```

`src` у задачи с олимпиады — олимпиада, год, этап, класс, номер и ссылка на официальный
архив; задача приписывается олимпиаде только после сверки условия и ответа по архиву.

## Подводные камни

- Своё состояние модели нельзя хранить в полях, которые использует движок: `t`, `done`,
  `playing`, `visible`, `p`, `m`, `g`, `tbl`, `note`, `drag`, `rng`. На этом уже обожглись:
  массив `f.done` движок принял за флаг «модель закончилась», и она не сделала ни шага.
- Моменты событий внутри шага (падение, вершина) ищите бисекцией (`root()` в `01.js`), а не
  линейной интерполяцией: на коротких полётах интерполяция давала расхождение до 0,06 %.
- `D.legend` рисует одну строку и на телефоне обрезается — используйте `legend()` из `01.js`.
